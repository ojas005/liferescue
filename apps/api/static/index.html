      HACKATHON DIFFERENTIATOR

      ⚖️ AI Governance & Deterministic Safety Engine

      "AI proposes. Deterministic safety policy decides." LifeRescue never allows an LLM unconstrained control over emergency dispatches or medical recommendations.

      Deterministic Safety Boundary Architecture:
      🤖
      AI Inference
      Proposes category, urgency & draft actions
      →
      📋
      Structured Output
      Strict Pydantic models reject extra/malformed fields
      →
      🛡️
      SafetyPolicyEngine
      Deterministic non-LLM Python code enforces rules
      →
      🔒
      Action Allowlist
      Prohibits unallowed actions & blocks dangerous verbs
      →
      🚑
      Governed Response
      Coordinated simulated dispatch & audit logging
      RULE 1

      Mandatory Life-Threat Escalation

      If acute symptoms (cardiac pain, choking, unconsciousness, severe hemorrhage) are detected in the incident text, the policy engine forces critical escalation and automatically injects an emergency dispatch action, even if an AI model hallucinated or proposed a lower urgency.

      RULE 2

      Strict Action Type Allowlist

      Only 5 vetted action types are permitted: CALL_EMERGENCY_SERVICES, NOTIFY_CONTACT, FIRST_AID_GUIDANCE, SCENE_SAFETY, and CUSTOM. Any external action proposed by an LLM outside this allowlist is blocked and omitted.

      RULE 3

      Prohibited Action Blocklists

      The safety engine deterministically screens all proposals against regex blocklists: medical prescriptions (prescribe, dose, inject), financial transfers (wire, crypto, credit), and shell execution (bash, rm -rf, powershell).

      RULE 4

      Defense-in-Depth Secret Redaction

      Every piece of text written to persistent storage or audit logs is filtered through proactive regex redactors. Leased credentials, tokens, and keys are scrubbed before SQLite commits or network serialization.
